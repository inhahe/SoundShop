No — .inc files are not a C++ language feature at all, and they’re definitely not new. They’re just a convention some projects use for files that are meant to be #include-d inside a .cpp.

What .inc actually is

To the compiler, this:

C++
#include "audio_nodes.inc"

is exactly the same as including any other text file. The preprocessor literally pastes the contents into the source file before compilation.

.inc is simply a naming hint to humans that:

  • the file is not a header

  • it is not meant to be included by multiple translation units

  • it is just a chunk of implementation code

Projects have used .inc files since the 1990s.

Why I used .inc here

Your juce_gui_server.cpp is likely very intertwined (JUCE host code usually is). Splitting it into real .h/.cpp files immediately can cause:

  • circular dependencies

  • missing forward declarations

  • large refactor effort

  • build system changes

Using .inc files gives you a safe first step:

juce_gui_server.cpp
    ├── protocol.inc
    ├── midi_scheduler.inc
    ├── audio_nodes.inc
    ├── plugin_host.inc
    └── main.inc

So you get:

✔ smaller files
✔ easier navigation
✔ zero linker issues
✔ no header refactor required

#include "JuceIncludes.h"

When .inc is commonly used

You'll see them in:

1. Large implementation splits

Game engines sometimes do this.

2. Template implementations

Example:

Vector.h
Vector.inl

3. Generated code

Compilers or code generators emit .inc.

4. Macro-driven tables

Example:

C++
#define OPCODE_LIST \
  X(Add) \
  X(Sub) \
  X(Mul)

#include "opcodes.inc"

Important rule

.inc files should only be included from one .cpp unless you know what you're doing.

Unlike headers, they don't have include guards.
